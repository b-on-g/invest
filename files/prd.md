# PRD — ВДО Rebalance (local-first $mol апп)

**Суть в одну строку:** закидываешь xlsx с квартилями ВДО → апп сравнивает с текущим портфелем и говорит, что купить/продать для ребаланса. Всё в браузере, без сервера. Ордера ставишь руками в Т-Банке.

Статус: draft v1 · стек: $mol + SheetJS · автор: Kir

---

## 1. Проблема и цель

Канал «Как приручить доходность» (kpd_investments) копит статистику по **momentum-премии в ВДО**: режет вселенную высокодоходных облиг на 4 квартиля по прошлой доходности и раз в квартал публикует составы. Идея стратегии — держать верхний квартиль (Q1), избегать нижнего (Q4), ребалансить раз в 3 месяца.

Хочется инструмент, который берёт этот снапшот и превращает его в конкретный список сделок под мой капитал — **без футгана авто-исполнения**. Решение считает, человек исполняет.

## 2. Что это НЕ (границы)

- **не** автономный торговый бот; никакого авто-трейда, никаких API-ключей в MVP
- **не** инвестрекомендация; тулза считает арифметику ребаланса, ответственность на пользователе
- **не** источник сигнала; сигнал (составы квартилей) приходит извне, апп ему доверяет

## 3. Понятия (глоссарий)

| термин | смысл |
|---|---|
| **ВДО** | высокодоходные облигации, junk bonds. Неформально: доходность ≥ ключевая ставка + 5 пп. Мелкие эмитенты, высокий купон = высокий риск дефолта |
| **momentum / премия за импульс** | факторная стратегия: покупать недавних лидеров, статистически они склонны продолжать обгонять. Хорошо изучена на ликвидных акциях, спорна на неликвиде |
| **квартиль Q1–Q4** | деление вселенной ВДО по прошлой доходности. Q1 = верхний (лидеры), Q4 = аутсайдеры |
| **доля в Q** | вес бумаги внутри квартиля (в файле суммируется ~в 100%) |
| **ребаланс** | пересборка корзины под свежий состав квартиля, раз в 3 мес |
| **local-first** | все данные и расчёт в браузере; сервера нет, файл не уходит с машины |
| **human-in-the-loop** | апп даёт список сделок, человек проверяет и ставит ордера сам |
| **лот** | минимальная торгуемая единица; для облиг = 1 бумага (~1000 ₽ номинала, цена гуляет) |
| **спред** | разница цен покупки/продажи; на неликвиде широкий, ест доходность |
| **ликвидность** | насколько легко купить/продать по рыночной цене; у ВДО обычно низкая |
| **дефолт-риск** | эмитент не платит купон/номинал; для ВДО реальный, не гипотетический |
| **FIGI / instrument_uid** | идентификаторы инструмента в T-Bank INVEST API (нужны на фазе импорта портфеля/цен) |
| **GIGO** | garbage in, garbage out — плохой вход даёт плохой выход независимо от кода |

## 4. Риски и честные оговорки → требования к UI

Стратегия имеет проблемы, которые апп обязан **показывать**, а не прятать:

1. **Ликвидность.** 110–135 микровыпусков, многие торгуются пару лотов в день. Спред + комса на квартальном ребалансе легко съедают momentum-премию.
2. **Квантизация.** При малом капитале мелкие имена (вес 0.37%) превращаются в 1–2 облиги или в ноль. Проверено: при 500k ₽ на Q1 хвост корзины ~1.8–2k ₽ на имя.
3. **Эдж не доказан.** Автор канала сам ещё копит статистику — не факт, что стратегия платит после издержек.
4. **Стухший снапшот.** Составы — ручная публикация из телеги; к моменту сделки данные могут быть старыми.
5. **Дефолт-риск** без кредитного фильтра.

**Отсюда фичи честности (must):**
- предупреждение «капитала мало, корзина квантуется» при малом capital/кол-ве бумаг
- тумблер «только ликвидный сабсет» с пере-нормировкой весов
- пометка неторгуемых/просроченных имён
- показ количества ордеров и грубой оценки издержек (спред×оборот)

## 5. Функциональные требования

**MVP:**
- импорт xlsx (SheetJS), чтение всех листов Qx с колонками `облигация` / `доля в Q`
- выбор целевого квартиля (Q1–Q4)
- ввод капитала (₽) и порога ордера (не дёргаться из-за копеек)
- ввод/импорт текущего портфеля (paste или пусто = первая покупка)
- расчёт diff → список **продать/купить в ₽**, сортировка: сначала продажи, потом покупки
- нормировка весов к 100%, Σ target = капитал
- предупреждения из §4

**Позже:**
- импорт выгрузки портфеля Т-Банка (даёт и текущие позиции, и цены)
- точные **лоты** (нужны цены)
- фильтр ликвидного сабсета (нужен источник оборотов)
- экспорт списка ордеров (csv / буфер)
- персист последнего портфеля в `$mol_state_local`

## 6. Нефункциональные требования

- **local-only**: ни один байт xlsx/портфеля не уходит с машины; нет бэкенда
- **без секретов**: в MVP никаких токенов брокера
- **стек $mol**: реактивность/хранилище/UI в одном; апп остаётся крошечным, работает офлайн
- **детерминизм**: одинаковый вход → одинаковый список сделок; логика ядра юнит-тестируема

## 7. Архитектура

```
xlsx ──► loadQuartiles() ──► normalizeWeights() ──► targetRub(capital)
                                                          │
current portfolio ────────────────────────────────► rebalance() ──► Order[] (buy/sell в ₽)
                                                          │
                                                     $mol view ──► список сделок + предупреждения
```

- **Ядро** — `rebalance.ts`, чистый TS, framework-agnostic (зависимость только SheetJS). Функции: `loadQuartiles`, `normalizeWeights`, `restrictTo`, `targetRub`, `rebalance`, `normName`.
- **View** — `$my_vdo_rebalance $mol_view`: `$mol_file`/дроп (xlsx), `$mol_switch` (квартиль), `$mol_number` (капитал, порог), тумблер ликвидности, `$mol_list` (результат). Логика — в `@ $mol_mem` поверх ядра. Файл читается реактивно → пересчёт протекает в список.
- **Опц. фаза T-Bank** — только read-only, для цен/портфеля. Ломает «no token» → отдельная фаза, не MVP. Go SDK нужен только для будущего бэкенд-бота, не для web-аппа.

## 8. Данные

**Вход 1 — xlsx квартилей** (пример: `ВДО Q1-Q4 на июль 2026.xlsx`):
- листы `Q1`,`Q2`,`Q3`,`Q4`; колонки `облигация` (укороченное биржевое имя, напр. `АПРИ 2Р10`), `доля в Q`
- ~110–135 строк на лист; сумма долей ~100 (нормируем)
- имена — не тикеры/ISIN → нужен `normName` для сопоставления (аптрим, схлоп пробелов, P/Р→P). Держать `displayName` (показ) отдельно от `key` (матч)

**Вход 2 — текущий портфель:** пока paste (имя → стоимость позиции ₽); позже — выгрузка Т-Банка.

**Цены:** локально взять негде без API. MVP работает **в ₽** (перевод в лоты — в приложении Т-Банка при выставлении). Точные лоты — когда появятся цены (фаза импорта портфеля).

## 9. Роадмап по фазам

- **Ф0 — бэктестер (до денег, вне аппа):** восстановить momentum-ранжирование из истории цен, симулировать квартальный ребаланс с реалистичным спредом+комсой на ликвидном сабсете. Вопрос: эдж выживает после издержек? Если нет — дальше не идём.
- **Ф1 — MVP:** xlsx → diff в ₽, $mol shell, предупреждения. *(ядро готово)*
- **Ф2 — импорт портфеля Т-Банка:** current + цены → точные лоты.
- **Ф3 — ликвидный фильтр** + оценка издержек.
- **Ф4 — экспорт ордеров, полировка.**
